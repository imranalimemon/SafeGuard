# Known limitations and open work

- **Detection misses:** at retained confidence 0.50, person recall was 0.7596 test / 0.8027 validation. Helmet recall was 0.9137 / 0.9090. Sources: [test metrics](evidence/phase3/test/metrics.json), [validation metrics](evidence/phase3/valid/metrics.json), produced by `evaluate_onnx.py`. Missed people cannot receive PPE checks. Occlusion, small objects, lighting and annotation quality remain risks.
- **Leakage:** test and validation images were pooled in augmentation. Present metrics are likely optimistic. A clean split/retrain/evaluation is pending. Historical training logs and current ONNX export provenance are not equivalent evidence.
- **Thresholded AP:** preserving production confidence 0.50 truncates PR/AP. These are not full-score COCO/Ultralytics benchmark values. Independent low-score evaluation needs an agreed evaluation-only threshold policy.
- **Worker ground truth:** YOLO boxes do not encode PPE relationships, exhaustive label completeness, or face orientation/visibility. Current worker evaluation uses geometric proxies and excludes ambiguous/unknown cases. No confirmed fully compliant ground-truth workers were derived, so full compliance precision/recall is unavailable. Human-reviewed balanced labels are needed.
- **Mask visibility:** the frontal-face/size heuristic is fallible; it is not a learned orientation guarantee. Distant, back-facing or occluded faces may remain unknown. Unknown is not compliant, and does not raise a missing-mask alert. False visible-face decisions can still cause false violations.
- **CPU speed:** the reproducible current replay benchmark measured mean 258.248 ms per detection, 14.887 delivered FPS with sampling/cached annotations, and mean 14.050 ms local frame age. These are different quantities. [Command/raw output](evidence/phase2/benchmark/benchmark.json). Delivered FPS is not fresh-detection FPS; cached boxes can lag. Local ACK-sink timing excludes browser/network/camera buffering. GPU/DirectML hardware performance is unverified.
- **Deduplication:** source/position/missing-items keys are not identity tracking. Movement can create new keys; nearby workers can collide; restarting clears in-memory cooldowns. Exactly-once alerts are not guaranteed across SMTP and SQLite failures.
- **Observation bias:** repeated frames/viewers count workers repeatedly. Compliance trends describe sampled observations, not unique headcount, attendance or exposure-adjusted risk. No old compliance is invented from violation-only history.
- **Capture/scale:** each viewer owns a capture; shared CPU/model capacity limits concurrency. Camera drivers may ignore timeout/shutdown requests. Reconnect attempts are bounded. Physical webcam/LAN discovery/reconnect and sustained deployment load require local testing.
- **Alerts:** real SMTP/WhatsApp delivery was not tested. Configuration status does not prove remote authentication/reachability. Preview and fake-transport tests prove guards/content/log behavior, not remote delivery. Restart clears live confirmation.
- **Access/deployment:** one admin, no roles, password reset or key recovery. Retain the encryption key securely; old backups may contain plaintext camera credentials. Use HTTPS/secure cookies/restricted network access outside loopback. Vite is a development server, not the production deployment plan.
- **UI/build:** specified desktop/tablet layouts and basic keyboard behavior were checked; formal accessibility, native Linux device behavior and every browser/device were not. Production build warns about a large bundle; code splitting remains possible. Locally bundled fonts remove a previously observed external-load dependency.
